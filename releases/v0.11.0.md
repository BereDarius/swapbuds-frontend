# Release v0.11.0 - Real-Time Messaging Improvements

**Release Date:** November 2025
**Version:** 0.11.0
**Type:** Feature Release

## 🎯 Overview

This release delivers critical improvements to the real-time messaging system, fixing stale data issues and adding instant read indicators. Users now see message badge updates immediately, conversations always show the latest messages when navigating, and senders receive real-time read receipts (blue checkmarks) when recipients open conversations.

## ✨ New Features

### Real-Time Read Indicators

- **Conversation Read Events**: Added WebSocket listener for `conversationRead` events from backend
- **Instant Blue Checkmarks**: Message senders now see double blue checkmarks (✓✓) appear immediately when recipients open conversations
- **Bulk Read Status**: All messages in a conversation marked as read simultaneously when recipient opens chat
- **Visual Feedback**: Clear distinction between sent (✓) and read (✓✓) status with blue checkmark color

### Data Freshness Improvements

- **Always Fresh Messages**: Conversation page (`/messages/[id]`) now always refetches messages when opened, ensuring latest messages display
- **Always Fresh Conversations**: Messages list page (`/messages`) always refetches conversations when navigated to
- **No Stale Cache**: Set `staleTime: 0` on critical message queries to prevent showing cached outdated data
- **Reliable Navigation**: Badge clicks, direct URL access, and page navigation all show current data

### Badge Update Enhancements

- **Instant Badge Reset**: Message badge count resets to 0 immediately when user opens conversation (no delay)
- **Global Count Invalidation**: Opening conversations now invalidates global unread count query in navbar
- **Real-Time Synchronization**: Badge counts stay synchronized across all tabs and navigation paths

## 🏗️ Technical Implementation

### WebSocket Integration

**New Event Listeners:**

- Added `onConversationRead` hook usage in conversation page
- Listens for backend `conversationRead` event with `{ conversationId, count }` payload
- Updates all message read status in React Query cache when event received

**Implementation:**

```typescript
// Listen for conversation read events
useEffect(() => {
  const unsubscribe = onConversationRead((data) => {
    if (data.conversationId === conversationId) {
      // Mark ALL messages as read in UI cache
      queryClient.setQueryData<InfiniteData<MessagesResponse>>(
        ["messages", conversationId],
        (old) => {
          if (!old) return old;
          const pages = old.pages.map((page) => ({
            ...page,
            messages: page.messages.map((m: Message) => ({
              ...m,
              isRead: true,
              readAt: new Date(),
            })),
          }));
          return { ...old, pages };
        },
      );
    }
  });
  return unsubscribe;
}, [conversationId, onConversationRead, queryClient]);
```

### React Query Configuration

**Messages List Page (`/messages/page.tsx`):**

```typescript
const { data: conversations = [], isLoading } = useQuery({
  queryKey: ["conversations"],
  queryFn: getConversations,
  staleTime: 0, // Always consider stale
  refetchOnMount: "always", // Always refetch
});
```

**Conversation Page (`/messages/[id]/page.tsx`):**

```typescript
const {
  data: messagesData,
  isLoading: messagesLoading,
  fetchNextPage,
  hasNextPage,
  isFetchingNextPage,
} = useInfiniteQuery({
  queryKey: ["messages", conversationId],
  queryFn: ({ pageParam = 1 }) =>
    getMessages(conversationId, { page: pageParam, limit: 50 }),
  enabled: !!conversationId,
  staleTime: 0, // Always consider stale
  refetchOnMount: "always", // Always refetch
  // ... pagination config
});
```

### Badge Count Invalidation

**Enhanced `markConversationAsRead` Flow:**

```typescript
markConversationAsRead(conversationId)
  .then(() => {
    // Invalidate global unread count to update navbar badge
    queryClient.invalidateQueries({
      queryKey: ["messages", "unread-count"],
    });
  })
  .catch(() => {
    // Silently fail - not critical
  });
```

## 📊 Performance Considerations

### Query Behavior

- **Before**: Conversations and messages cached indefinitely, showing stale data
- **After**: Queries set to `staleTime: 0`, always refetch on mount
- **Impact**: Slightly more API calls, but ensures data freshness
- **Optimization**: WebSocket events still update cache in real-time, reducing need for manual refetches

### Cache Strategy

- Real-time updates via WebSocket events (instant, no API call)
- Refetch on mount catches any missed events during offline periods
- Infinite scroll pagination still cached for smooth scrolling
- No performance degradation observed in testing

### Network Usage

- Additional API calls only on page navigation (mount)
- WebSocket events remain lightweight (<1KB per event)
- Badge count endpoint cached for 60 seconds on backend (Redis)
- Overall network usage increase: minimal
