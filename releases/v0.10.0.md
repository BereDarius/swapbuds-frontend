# Release v0.10.0 - Real-time Notifications & UX Enhancements

**Release Date:** November 2025
**Version:** 0.10.0
**Type:** Feature Release

## 🎯 Overview

This release introduces real-time WebSocket-powered notification updates, comprehensive UX improvements for authentication, messaging, item interactions, and support chat. Users now experience instant notification badge updates, improved error handling, session management, and an enhanced messaging flow that respects user intent.

## ✨ New Features

### Real-time Notifications

- **Separate Notification Counts**: Message notifications (unread count) and general notifications now display separately in the navbar with distinct badges
- **WebSocket Integration**: Both message and notification counts update in real-time via WebSocket events without page refresh
- **Polling Fallback**: 30-second polling ensures counts stay updated even if WebSocket connection drops
- **Instant Feedback**: New messages and notifications immediately reflect in navbar badges

### Authentication Enhancements

- **Error Display**: Login and register pages now show clear error messages in styled error boxes
- **Legal Document Versioning**: Registration dynamically fetches and submits current TOS and Privacy Policy versions
- **Remember Me Functionality**: Token storage switches between localStorage (persistent) and sessionStorage (session-only) based on user preference
- **Smart Redirects**: Authenticated users automatically redirected from auth pages; 401 errors only trigger logout for non-auth endpoints
- **Loading States**: Registration form disables while legal documents load, shows clear status messages

### Messaging System Redesign

- **New Message Compose Page**: Dedicated `/messages/new` page for composing first message to a user
- **No Auto-send**: Profile "Message" button now navigates to compose page instead of automatically sending a message
- **Custom Message Input**: Users can write personalized first messages with 6-row textarea
- **Existing Conversation Detection**: Automatically redirects if conversation with user already exists
- **Validation**: Checks for userId and username parameters before allowing message composition

### Item Detail Enhancements

- **Like/Comment System**: Fully functional like button with filled/unfilled states and comment dialog
- **Image Modal**: Click images to view in full-screen modal with large aspect-ratio view
- **Comment Dialog**: View and add comments directly from item detail page with real-time updates
- **Owner Restrictions**: Like, comment, and flag buttons hidden for item owners to prevent self-interaction
- **Interactive Stats**: Click like/comment counts to trigger respective actions
- **Loading States**: Spinners during like and comment submission

### Support Chat Fixes

- **Message Display Logic**: Fixed sender detection - checks `isOwn` first, then determines `isAgent` based on role
- **Field Name Consistency**: Updated to use `senderId` and `sender` fields matching backend Prisma schema
- **API Endpoint**: Corrected POST endpoint from `/support/chats` to `/support/chat` (singular)
- **JWT Field Access**: Changed all `req.user.userId` to `req.user.id` throughout support controller

### Notification Management

- **Mark All Read**: Single API call to mark all notifications as read with loading spinner
- **Optimized Performance**: Replaced forEach loop with bulk operation mutation
- **Real-time Updates**: Notifications update instantly via WebSocket listeners

## 🏗️ Technical Implementation

### Real-time Notification System

- WebSocket hooks (`useMessagesSocket`, `useNotificationsSocket`) integrated in main layout
- Event listeners (`onMessage`, `onNotification`) invalidate React Query cache on new items
- Query keys: `["messages", "unread-count"]` and `["notifications", "unread-count"]`
- 30-second `refetchInterval` as fallback for connection issues
- Cleanup functions in useEffect hooks to unsubscribe on unmount

### Session Management

- **Remember Me**: localStorage for persistent sessions, sessionStorage for temporary
- Auth store checks `rememberMe` preference before choosing storage location
- API client reads from both storage types when attaching JWT token
- Logout clears both storage locations and rememberMe preference
- 401 interceptor skips redirect for `/auth/login` and `/auth/register` endpoints

### API Client Improvements

- Token retrieval checks both localStorage and sessionStorage
- 401 error handler distinguishes between auth failures and authenticated endpoint issues
- Prevents redirect loops on login/register failures
- Clears all auth-related storage items on logout

### Messages API

- Fixed `getMessages()` endpoint to `/messages/conversations/${id}` (removed `/messages` suffix)
- Created conversation on first message send via `sendMessage()` API
- Conversation existence check before allowing new message composition

### Support API

- POST endpoint corrected to `/support/chat` (singular)
- Backend uses `senderId` and `sender` fields in SupportMessage model
- JWT strategy returns `user.id` (not `userId`) with `role` field included

### State Management

- React Query for server state (items, messages, notifications)
- Zustand for auth state with localStorage/sessionStorage persistence
- Query invalidation triggers automatic UI updates on WebSocket events
