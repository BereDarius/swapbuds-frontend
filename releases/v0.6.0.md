# Release v0.6.0 - Messaging System

**Release Date:** November 24, 2025
**Type:** Major Feature Release

---

## 🎉 Overview

This release implements the complete **Messaging System**, enabling real-time communication between users. The messaging system is fully integrated with the trade system and user profiles, allowing traders to discuss their exchanges seamlessly.

---

## ✨ New Features

### Messaging System (Complete)

#### Types & API

- **Message Types**: Comprehensive TypeScript definitions for messages and conversations

  - `Message`: Full message entity with sender info, read status, timestamps
  - `Conversation`: Conversation entity with participants, last message preview, unread count
  - `MessageSender`: User information for message display
  - `ConversationUser`: Extended user info for conversation participants
  - `ConversationTrade`: Trade context when conversation is linked to a trade

- **API Client**: Complete messaging API with 7 functions
  - `getConversations()`: Fetch all user's conversations
  - `getMessages(conversationId, params)`: Get paginated messages in a conversation
  - `sendMessage(data)`: Send a new message
  - `markMessageAsRead(messageId)`: Mark specific message as read
  - `markConversationAsRead(conversationId)`: Mark all messages in conversation as read
  - `getUnreadCount()`: Get total unread message count
  - `deleteMessage(messageId)`: Soft delete a message

#### Components

- **ConversationCard**: Displays conversation summaries in list view

  - User avatar and username with active/inactive status
  - Last message preview with timestamp
  - Unread message count badge
  - Trade context display when applicable (trade status, items)
  - Hover effects and click navigation

- **MessageBubble**: Individual message display in chat interface
  - Sender avatar (shown selectively to reduce clutter)
  - Message content with proper text wrapping
  - Timestamp in HH:mm format
  - Read receipts for sent messages (single/double check marks)
  - Different styling for own vs. other user's messages
  - Supports avatars for group-like conversations

#### Pages

- **Messages Listing** (`/messages`)

  - Complete list of user's conversations
  - Real-time sorting by last message time
  - Search functionality to filter by username
  - Empty states with CTAs:
    - No conversations: Link to browse trades
    - No search results: Clear search suggestion
  - Unread count displayed on each conversation
  - Trade context badges when applicable

- **Conversation Detail** (`/messages/[id]`)
  - Full chat interface with message history
  - Header showing:
    - Other user's avatar and username
    - Active/inactive status badge
    - "View Profile" button
    - Trade context card (when applicable) with link to trade
  - **Message Area**:
    - Scrollable message history (400-600px height)
    - Messages reverse-ordered (newest at bottom)
    - Auto-scroll to latest message
    - Smart avatar display (only on sender change)
    - Empty state for new conversations
  - **Message Input**:
    - Multi-line textarea (5000 char limit)
    - Character counter
    - Send button (keyboard shortcut: Enter to send, Shift+Enter for new line)
    - Disabled state while sending
  - **Real-time Features**:
    - Auto-refresh every 5 seconds (polling)
    - Automatic mark as read on view
    - Instant UI updates on send
    - Query invalidation to sync conversations list

#### Integration with Existing Features

- **Trade Detail Page** (`/trades/[id]`):

  - "Message User" button for both proposer and responder
  - Button only shown to the other party (not self)
  - Checks for existing conversation and navigates if found
  - Shows info toast when no conversation exists yet

- **User Profile Page** (`/profile/[username]`):
  - "Message User" button (only shown on other users' profiles)
  - Replaces "Edit Profile" button when viewing others
  - Same conversation detection and navigation logic
  - Consistent with trade messaging UX

## 🔧 Technical Implementation

### Real-time Messaging

- **Polling Strategy**: Messages refresh every 5 seconds using TanStack Query's `refetchInterval`
- **Optimistic Updates**: Message send immediately updates UI before server confirmation
- **Query Invalidation**: Conversations list updates when messages are sent
- **Auto-scroll**: Messages container automatically scrolls to bottom on new messages

### State Management

- **TanStack Query**: All messaging data cached and synchronized
  - `['conversations']`: User's conversation list
  - `['messages', conversationId]`: Messages in specific conversation
- **Zustand**: User authentication for sender identification
- **React State**: Local form state for message input and UI interactions

### Data Flow

1. **Sending Message**:

   ```
   User types → Submit → API call → Success → Update UI → Invalidate queries → Refresh lists
   ```

2. **Viewing Conversation**:

   ```
   Click conversation → Fetch messages → Mark as read → Poll for updates → Auto-scroll
   ```

3. **Navigation**:
   ```
   Message button → Check existing conversation → Navigate or show info toast
   ```

### Error Handling

- Network errors displayed via toast notifications
- Failed message sends keep input text for retry
- Graceful degradation when conversation not found
- Loading states for all async operations

### Performance Optimizations

- Pagination support (50 messages per page)
- Conversation search uses client-side filtering (fast for reasonable dataset)
- Messages only fetched when conversation is active
- Auto-scroll only triggers on message changes
- Selective avatar rendering reduces DOM nodes

## 🚀 Migration Notes

### For Developers

1. **No Breaking Changes**: All additions are new features, existing code unaffected
2. **Dependencies**: No new packages required (uses existing date-fns, lucide-react)
3. **API Alignment**: Frontend expects backend endpoints:
   - `GET /messages/conversations`
   - `GET /messages/conversations/:id`
   - `POST /messages`
   - `PATCH /messages/:id/read`
   - `PATCH /messages/conversations/:id/read`
   - `GET /messages/unread/count`
   - `DELETE /messages/:id`

### For Users

- New "Messages" section accessible from main navigation (implementation pending)
- Message buttons appear on trade detail pages and user profiles
- No setup required - conversations created automatically on first message

---

## 🐛 Known Limitations

1. **Conversation Creation**:

   - Conversations are created by backend on first message send
   - Frontend shows info toast when no conversation exists (instead of auto-creating)
   - This is by design to prevent empty conversations

2. **Real-time Updates**:

   - Currently using 5-second polling
   - Future enhancement: WebSocket integration for true real-time updates

3. **Typing Indicators**: Not implemented in this release

4. **Message Notifications**: Desktop/push notifications planned for future release

5. **Message Search**: Global message content search not yet available
